Reflection — SIS401 Programming Assignment 2

Design decisions. I split the system into a local layer and a cloud layer. Mosquitto and Node-RED run on the Raspberry Pi, so the dashboard and LED control keep working even without internet access, while ThingsBoard provides cloud storage, device management and alarms. Node-RED forwards telemetry to the cloud rather than the ESP32 connecting directly, which keeps the firmware simpler and lets me filter and reshape data in one place. Each reading is published as a single JSON message so all values share one timestamp, under a hierarchical topic structure that supports more devices. I chose an LED as the actuator and extended it with dimming and an automatic night-light mode. Given my cybersecurity focus, I disabled anonymous broker access and validated every command on the ESP32.

Challenges. The DHT22 initially returned failed readings, which I traced to the wiring and fixed by reconnecting the sensor carefully on the breadboard. The light sensor jumped between 0 and 100 % because of a loose ground wire. Connecting to ThingsBoard was refused as "not authorised" until I matched the MQTT host to the ThingsBoard server where my device was registered. I also had to install Dashboard 2.0 alongside the older Node-RED dashboard on the Pi, and reset a forgotten Node-RED editor password.

Improvements. I would enable TLS on port 8883 for both the local broker and ThingsBoard, and use ThingsBoard RPC so the LED could also be controlled from the cloud. I would store long-term history in InfluxDB with Grafana, calibrate the light sensor to lux, and add the Edge Impulse extension to classify environmental conditions directly on the ESP32.
